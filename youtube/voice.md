# 나레이션 보이스 결정

**채널의 기억 4번째 파일.** 보이스는 룩만큼이나 채널 정체성이다.
**한 번 정하면 바꾸지 않는다.** 편마다 목소리가 다르면 시청자가 채널을 못 알아본다.

## 결정: 보이스 성격을 먼저 고정하고, 그 조건에 맞는 상품을 고른다

서비스보다 **보이스의 성격**이 먼저다. 서비스는 갈아탈 수 있지만 성격이 흔들리면 채널이 흔들린다.

### 보이스 스펙 (확정)

| 항목 | 값 | 이유 |
|---|---|---|
| 성별·연령 | **남성, 30~40대** | 이 채널의 소재는 실패와 한계다. 차분한 저음이 그 톤에 맞는다 |
| 톤 | **낮고 건조하게. 무감정에 가깝게** | `channel-brief.md` 톤 규칙: 감탄사 대신 수치로 말한다 |
| 속도 | **표준의 0.9~0.95배** | 숫자를 읽는 채널이다. 빠르면 숫자가 안 박힌다 |
| 억양 | **평탄하게.** 문장 끝을 올리지 않는다 | 올리면 광고 톤이 된다 |
| 강조 | **없음.** 강조는 화면이 한다 | 목소리까지 세면 과해진다 |

### 피할 것
- **뉴스 앵커 톤** — 과장돼 있고, 이 채널이 하지 않는 "충격/소름" 화법과 붙는다
- **밝고 친근한 톤** — 소재가 실패인데 목소리가 밝으면 어긋난다
- **감정 연기형 보이스** — 자막이 본문인 채널에서 연기는 방해다

### 핵심 원칙
**이 채널에서 나레이션은 주연이 아니다.** 자막이 본문이고, 시청자는 소리를 끄고 본다.
목소리는 **소리를 켠 사람에게만 주는 보조 트랙**이다.
그래서 좋은 보이스의 기준은 "매력적인가"가 아니라 **"화면을 방해하지 않는가"**다.
지루할 정도로 담백한 게 맞다.

## 결정: **Supertonic 3 · 보이스 sid 7** (무료, 로컬)

처음엔 타입캐스트(월 9,900원)를 1순위로 잡았다. 공개 모델을 조사하다가
**Supertonic 3**(서울 Supertone Inc.)를 찾아 바꿨다 — 한국어 지원, **GPU 없이 CPU로** 돈다.
6초짜리 음성을 1.3초에 만든다.

| 항목 | 값 |
|---|---|
| 모델 | Supertonic 3 (int8, sherpa-onnx 패키징) |
| 라이선스 | 코드 MIT / **모델 OpenRAIL-M** — 상업 이용 가능, 유해한 용도 금지 조건부 |
| 받는 곳 | sherpa-onnx 공식 GitHub 릴리스 (HuggingFace가 막힌 환경이라) — `fetch-models.sh` |
| 보이스 | **sid 7** (남성) |
| 속도 | 0.90 |
| seed | 줄마다 고정 (`scenes/<회차>/voice-seeds.json`) |

### sid 7을 고른 근거 — 들을 수 없어서 쟀다

10종을 같은 문장으로 생성해 음높이(F0)와 억양 폭을 측정했다. 0~4는 여성, 5~9는 남성이다.

| sid | 중앙 F0 | 억양 폭 (반음, 10~90%) |
|---|---|---|
| 5 | 131.2 Hz | 8.0 |
| 6 | 102.1 Hz | 6.8 |
| **7** | **106.0 Hz** | **5.5 — 가장 평탄** |
| 8 | 118.5 Hz | 8.2 |
| 9 | 93.5 Hz | 7.6 |

스펙은 "낮고 건조하게, 강조 없이"다. 9번이 가장 낮지만 억양이 크다.
**7번은 충분히 낮으면서 억양이 가장 평탄하다.** 말도 가장 빨라 0.9배로 늦출 여유가 있다.

### 나레이션 검수 — 음성 인식으로 되받아 적는다

에이전트는 소리를 들을 수 없다. 그래서 만든 클립을 **한국어 음성 인식기**
(zipformer-korean, 한국어 음성 코퍼스로 학습)로 다시 받아 적어 대본과 대조한다.

- 처음 쓴 다국어 인식기(SenseVoice)는 **자기 예제 한국어 음성조차 한자로 깨뜨려** 버렸다.
  검수 도구부터 검증해야 한다는 교훈이다
- 인식기가 `23cm`, `180도`처럼 숫자로 적는 건 한자어 수사로 되돌려 비교한다
- 인식기는 **표준 발음**대로 적는다. `엿처럼→여처럼`, `장비만이→장비많이`는 틀린 게 아니다

### seed를 줄마다 고르는 이유

같은 목소리라도 seed에 따라 발음이 달라진다. `--search`는 줄마다 5개 후보를 생성해
인식 오류가 가장 적은 것을 고르고 기록한다. 기록이 남으니 다음 빌드는 탐색 없이 같은 소리가 난다.

### 숫자 읽기 규칙 (001화에서 배움)

`만 이천이백육십이 미터`는 이 목소리가 **끝의 `이`를 `미터`에 삼켜 12,260으로 들렸다.**
seed를 바꿔도 불안정했다. **반복 음절이 긴 숫자를 나레이션에 넣지 않는다.**
정확한 숫자는 화면이 보여준다. 나레이션은 **발음이 확실하고 사실로도 참인 말**로 한다
(`십이 킬로미터가 넘는 깊이` — 12.262km이므로 참).

## 워크플로 (보이스가 정해진 뒤)

```bash
cd youtube/render
./fetch-models.sh                                   # 최초 1회
node vo.mjs 001-deepest-hole                        # 대본 + 타임코드 명세
python3 tts_supertonic.py 001-deepest-hole --search # 새 회차: seed 탐색 + 인식 대조
python3 tts_supertonic.py 001-deepest-hole          # 재빌드: 기록된 seed로 재현
node build.mjs 001-deepest-hole --vo out/001-deepest-hole/vo --bgm
```

**나레이션을 한 통으로 뽑지 않는다.** 줄 단위로 뽑아 각자의 시각에 꽂는다.
한 통으로 뽑으면 화면 타이밍과 반드시 어긋나고, 어긋나면 화면을 다시 맞춰야 한다.
`vo.mjs`가 각 줄이 자기 구간에 들어가는지 미리 검사한다 — 001화에서 실제로 두 줄이 걸려서
씬을 57초에서 59초로 늘렸다.

## TTS 녹음 설정
- 포맷: WAV, 48kHz, 모노 (생성기가 맞춘다)
- 레벨 정규화는 하지 마라. `build.mjs`가 -14 LUFS로 맞춘다
- 문장 앞뒤 무음은 최소로. 클립 시작이 곧 발화 시작이어야 한다
