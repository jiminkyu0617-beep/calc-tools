# 브랜드 자산

전부 코드로 만든다. `theme.css`를 공유하므로 영상과 채널 페이지의 룩이 자동으로 일치한다.

```bash
cd youtube/render
node still.mjs profile 800 800     # 프로필
node still.mjs banner 2560 1440    # 배너
node sfx.mjs                        # 효과음 3종
```

## 마크

**막대 위의 점.** 자(尺) 위에서 멈춘 지점 — 채널 이름 그대로다.

점은 **1/3 지점**에 있다. 001화의 "지각의 3분의 1"에서 왔고, 가운데가 아니라서
슬라이더나 지도 핀으로 안 읽힌다. 비대칭이 식별성을 만든다.

댓글창에서는 24px까지 줄어든다. **그 크기에서 글자는 죽고 형태만 남는다.**
그래서 마크에 글자를 넣지 않았다.

## 프로필 (800×800)

- 유튜브가 **원형으로 자른다.** 모든 요소를 반지름 400 안에 두었다
  (막대 모서리 최대 반경 312.8 / 점 최대 반경 208.5 — 검산 완료)
- PNG로 올린다. 도형과 단색이라 JPG는 가장자리가 뭉개진다

## 배너 (2560×1440)

- 안전 영역 수치가 출처마다 **1235×338**과 **1546×423**으로 갈린다.
  → **더 작은 쪽(1235×338)** 안에만 핵심 요소를 두었다. 어느 쪽이 맞든 잘리지 않는다
- 문구: `한계선` / `어디까지 갔고, 왜 거기서 멈췄나` / `쇼츠 · 주 2~3편`
- **발행 주기를 "평일 07:30"으로 쓰려다 고쳤다.** 제작 여력은 주 2~3편이다.
  배너가 지키지 못할 약속을 하면 안 된다

## 효과음 (3종)

세 개뿐이다. 룩북 규칙 — **의미 있는 순간에만.**

| 파일 | 언제 | 소리 |
|---|---|---|
| `lock.wav` | 숫자가 확정되는 순간 | 낮은 몸통 + 아주 짧은 딸깍 (0.18초) |
| `open.wav` | 형태가 열리는 순간 | 낮은 데서 살짝 올라오는 스웰 (0.34초) |
| `shift.wav` | 축의 의미가 바뀌는 순간 | 마른 틱 하나 (0.045초) |

**전부 ffmpeg로 합성한다. 외부 소스가 없다** — 라이선스가 필요 없고, 같은 명령이
같은 파일을 만들고, 톤을 바꾸려면 `sfx.mjs`의 숫자를 고치면 된다.

세 소리의 피크는 **-18 dBFS로 자동 정렬**한다. 성분 볼륨을 손으로 맞추면 반드시 어긋난다
(감쇠 곡선이 저역에서 피크를 더 깎는다). 그래서 한 번 굽고 재서 게인을 계산해 다시 굽는다.

효과음은 **채널 공용 자산**이다. 회차마다 다른 소리를 쓰면 채널이 안 쌓인다.
회차별 배치 시각만 씬의 `sfx` 배열에 적고, `build.mjs --vo`가 자동으로 얹는다.

## BGM (`bgm/bed.wav`)

16초 루프. `build.mjs --bgm`이 영상 길이까지 이어 붙인다.

**멜로디가 없다.** 이 채널의 BGM은 "곡"이 아니라 "바닥"이다.
자막이 본문이고 나레이션이 보조인데 음악까지 주장하면 화면이 안 읽힌다.
A1(55Hz) 드론 + 0.5Hz 맥놀이 + 5도·옥타브, 900Hz 위는 잘라낸다 — 중고역이 있으면
나레이션과 자리를 다툰다.

**루프가 매끄러우려면 세 가지가 동시에 맞아야 한다.** 처음엔 이음매 점프가 1306이었다.
1. 각 성분이 16초에 정수 번 진동 (주파수가 0.0625 Hz의 배수)
2. **필터의 초기 과도응답을 잘라낸다** — lowpass/highpass는 t=0에서 정상 상태가 아니다.
   2초를 더 굽고 앞을 버린다. 그 지점에서도 위상이 0이어야 하므로 주파수는 0.5 Hz의 배수
3. **루프되지 않는 성분을 넣지 않는다** — 핑크 노이즈를 뺐다
→ 지금 이음매 점프는 13(32768 중). 무음 수준이다.

나레이션이 나오는 동안에는 사이드체인 압축으로 BGM이 자동으로 눌린다.

## 나레이션 — 임시 목소리

`tts.py`가 espeak-ng로 14줄을 만든다. **발행용이 아니다.** 포먼트 합성이라 기계음이 난다.

**그런데도 만드는 이유**: 목소리를 사기 전에 타이밍·믹스·덕킹·라우드니스가 실제로
맞는지 끝까지 확인할 수 있다. 진짜 목소리는 같은 파일 이름으로 갈아 끼우면 그만이다.

```bash
node vo.mjs 001-deepest-hole      # 대본 + 타임코드 명세
python3 tts.py 001-deepest-hole   # 임시 목소리 (구간 초과를 실측으로 잡는다)
node build.mjs 001-deepest-hole --vo out/001-deepest-hole/vo-placeholder --bgm
```

**실측이 추정을 교정했다.** 처음 5.0음절/초로 잡았더니 03번이 구간을 0.27초 넘겼다.
실측은 4.2~4.8이라 `vo.mjs`의 계수를 4.3으로 내렸고, 03번 문장을 줄였다.

## 라우드니스 — 2패스 + 압축

목표 -14 LUFS. **1패스 loudnorm으로는 -17.0에서 멈춘다.**

측정해 보니 입력 트루피크가 +0.05 dBTP(이미 클리핑)이고 피크-라우드니스 차가 21.5 dB였다.
-14를 트루피크 -1.5로 맞추려면 그 차가 12.5 dB 이하여야 한다 — **압축 없이는 닿을 수 없다.**

그래서 나레이션 버스에 압축(threshold 0.06 / ratio 3)과 리미터를 걸고,
메이크업 게인으로 되올린 뒤 2패스 정규화한다. 메이크업 값은 실측으로 정했다.

| makeup | 결과 |
|---|---|
| 0 | -16.5 LUFS |
| 4 | -15.3 LUFS |
| **7** | **-14.2 LUFS** ✅ |

유튜브는 시끄러운 영상을 낮추기만 하고 조용한 영상을 올려주지 않는다.
2 LU가 낮으면 다른 영상보다 작게 들린다.

> **TTS를 바꾸면 이 값을 다시 재야 한다.** 목소리마다 다이내믹이 다르다.
> `LN_DEBUG=1 node build.mjs ...`로 측정값을 보고 판단한다.

## 오디오 경로 검증

나레이션을 받기 전에 **효과음만으로 한 번 구워 봐야 한다.**

```bash
node build.mjs 001-deepest-hole --vo <빈 디렉터리>
```

001화에서 이 테스트가 실제 버그 두 개를 잡았다.
- **`-shortest`가 영상을 잘랐다.** 오디오가 50.5초에서 끝나자 59초 영상이 50.5초로 잘렸다.
  → `apad`로 오디오를 무음 연장해 영상이 길이 기준이 되게 고쳤다
- **샘플레이트가 96kHz로 튀었다.** loudnorm이 바꿔 놓는다 → `-ar 48000`으로 고정

둘 다 나레이션을 받은 뒤에 발견했으면 원인을 찾느라 한참 걸렸을 것이다.
