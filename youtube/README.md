# 유튜브 크리에이터 에이전트 팀

목표: **구독자 100만.**
이 디렉터리는 그 목표를 향한 제작 조직을 코드로 고정한 것이다. 정의 파일은 `.claude/agents/yt-*.md`.

## 이 팀이 도는 방식

영상을 만들고 끝나는 조직이 아니라 **닫힌 루프**다.

```
        ┌──────────────────────────────────────────────┐
        │                                              │
   소재 발굴 → 훅 검증 → 각본 → 연출 → 영상미 → 편집 → 패키징 → 검수 → 발행
        ↑                                              │
        │                                              ↓
   다음 편 지시 ← 리비전 ← 성과 분석 ← 댓글 대응 ←──── 발행 후 72시간
```

**루프가 한 바퀴 돌 때마다 세 가지가 갱신된다.**

1. `youtube/lookbook.md` — 영상미 기준선 (뭐가 예뻐 보였는지)
2. `youtube/hook-log.md` — 후킹 승패 기록 (뭐가 사람을 멈춰 세웠는지)
3. `youtube/channel-brief.md` — 채널 정체성 (반복 검증된 것만 승격)
4. `youtube/voice.md` — 나레이션 보이스 (한 번 정하면 바꾸지 않는다)

이 세 파일이 채널의 기억이다. **에이전트는 매번 이걸 먼저 읽고 시작한다.**
그래서 20편째의 팀은 1편째의 팀보다 실제로 더 잘한다.

## 왜 역할을 쪼개는가

영상 제작이 실패하는 지점은 대부분 **한 사람이 자기 결과물을 자기가 판정할 때** 생긴다.
각본가는 자기 후킹이 약한 걸 못 보고, 편집자는 자기 컷의 지루함을 못 느낀다.
그래서 **생산 역할과 그것을 깨는 반대 역할을 물리적으로 분리**했다.

| 생산 | 그것을 깨는 반대 역할 |
|---|---|
| 각본가 (재미) | 검수관 (사실·권리·정책) |
| 패키저 (클릭 유도) | 검수관 (낚시 판정 = 반려) |
| 연출가 (하고 싶은 그림) | 편집자 (제작 공수·소스 확보 가능성) |
| 비주얼 (완성도) | 분석가 (예뻤는데 안 봤다는 숫자) |
| 팀 전체 (감) | 시청자 (댓글 — 커뮤니티가 받아 온다) |

검수관과 분석가는 **반려 권한**을 갖는다. 총괄이 뒤집으려면 근거를 남겨야 한다.

## 파이프라인

한 편은 `youtube/episodes/<번호>-<슬러그>/` 안에서 아래 순서로 파일이 쌓인다.
**앞 단계 산출물이 없으면 다음 단계는 시작하지 않는다.**

### 발행 전

```
00-brief.md      전략     이 편이 담당할 단일 KPI와 시청자
01-scout.md      발굴     소재 + 훅 후보 3개 + 흥미 근거
02-script.md     각본     초 단위 대본
03-direction.md  연출     샷 리스트·페이싱
04-visual.md     비주얼   룩 스펙 (색·타이포·모션·질감)
05-edit.md       편집     컷 지시서 + subtitles.srt
06-packaging.md  패키징   썸네일 3안 + 제목 5안
07-qa.md         검수     PASS / 조건부 / 반려
08-publish.md    발행     최종 제목·설명·태그·공개 일시
```

### 발행 후 (루프의 나머지 절반 — 여기가 진짜 일이다)

```
09-comments.md   커뮤니티 D+0~7 댓글 로그, 답변 기록, 채굴한 소재
10-report.md     분석     D+2 / D+7 지표, 병목 1개 지목, 다음 편 지시
11-revision.md   리비전   수정 결정과 그 결과 (전/후 지표)
```

### 게이트

| 게이트 | 시점 | 판정 |
|---|---|---|
| **G1 훅** | `01-scout.md` 후 | 훅 3개 중 "3초 안에 손 멈출 것" 하나도 없으면 **소재 폐기**. 아까워하지 않는다 |
| **G2 대본** | `02-script.md` 후 | 첫 3초에 인사·소개가 있으면 반려 |
| **G3 비주얼** | `05-edit.md` 후 | 룩북 기준 미달 항목이 3개 이상이면 반려 |
| **G4 검수** | `07-qa.md` | 검수관 반려는 **총괄도 못 뒤집는다** (사실·권리·정책) |
| **G5 발행** | `08-publish.md` | 제목이 약속한 것을 첫 30초에 주지 못하면 제목을 바꾼다 |
| **G6 리비전** | D+7 | 분석 결과에 따라 수정·유지·폐기 결정. 결정 안 하는 것은 금지 |

## 화면은 코드로 그린다

`youtube/render/` — 이 채널의 모든 화면이 나오는 곳.
`scene.html` → Chromium 프레임 캡처 → ffmpeg → 1080×1920 MP4.

외부 자료화면을 쓰지 않는다. 저작권 위험이 구조적으로 없고,
무엇보다 **다른 채널이 흉내 낼 수 없는 화면**이 남는다.
그리고 렌더가 결정론적이라 **"조금 고쳐서 다시 뽑기"가 실제로 된다** — 피드백 루프의 전제다.
자세한 건 [`youtube/render/README.md`](render/README.md).

## 사용법

```
/yt-episode <주제>        기획부터 발행 시트까지 한 편 제작
/yt-feedback <회차번호>    발행 후 루프 — 댓글 대응 + 성과 분석 + 리비전 판단
```

개별 호출도 된다: "yt-visual로 3화 룩 다시 잡아줘", "yt-community로 어제 댓글 답변 초안"

## 100만까지의 단계

| 단계 | 구독자 | 이 구간의 유일한 과제 | 루프 운영 |
|---|---|---|---|
| 0→1천 | **발견** | 뭐가 먹히는지 찾기 | 포맷 4종 병렬. 훅 로그가 자산의 전부 |
| 1천→1만 | **반복** | 먹힌 포맷 1개 양산 | 승리 훅 패턴 고정. 리비전으로 초기 편 구조 |
| 1만→10만 | **확장** | 유입 시청자를 팬으로 | 커뮤니티 비중 급증. 시리즈·세계관 |
| 10만→100만 | **시스템** | 감각을 공정으로 | 분석가 주도 주간 실험. 지시서만으로 외주 가능하게 |

**전략가가 단계 전환을 선언**하고, 그때 각본·연출·비주얼의 기준선을 갈아끼운다.
전 단계 기준을 다음 단계에서 계속 쓰는 것이 성장이 멈추는 가장 흔한 원인이다.

## 지표 기준선

출발선일 뿐이다. **데이터가 쌓이면 자기 채널 중앙값으로 교체한다.** 남의 평균을 끝까지 목표로 삼지 않는다.

| 지표 | 쇼츠 | 롱폼 |
|---|---|---|
| 후킹 구간 유지율 | 3초 80%+ | 30초 65%+ |
| 평균 시청 지속률 | 70%+ | 45%+ |
| 노출 클릭률 | — (피드 구조상 무의미) | 5%+ |
| 조회 대비 구독 전환 | 0.3%+ | 1%+ |
| 조회 대비 댓글 | 0.1%+ | 0.3%+ |
| 댓글 응답률 (발행 후 48h) | 초기 30개 100% | 초기 50개 100% |
